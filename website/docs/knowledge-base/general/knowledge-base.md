这里持续整理来自真实项目和工作流的技术经验，重点关注 **AI 自动化、软件工程、n8n、知识管理与开源实践**。目标不是追逐信息流，而是把已经解决的问题转化为可复现、可连接、可长期维护的知识。

## 你会在这里找到什么

- **AI 自动化**：模型、工具调用、智能代理与业务流程的可靠集成。
- **软件工程**：架构设计、代码质量、测试、部署与故障排查中的实际决策。
- **n8n**：工作流设计、节点集成、运行维护与自动化模式。
- **知识管理**：Markdown、Obsidian、双向链接和知识图谱的实践。
- **开源**：开放协作、项目维护和可复用工具。

## 内容原则

每篇文章尽量说明适用场景、前置约束、可执行步骤和验证结果。尚未经过实践验证的想法会与稳定结论明确区分，避免把推测包装成答案。

内容使用标准 Markdown 保存，并通过分类、标签与 `[[WikiLink]]` 建立联系。站点构建时会把这些关系加入文档知识图谱，帮助你从一篇文章继续探索相关主题。

## 从哪里开始

如果你准备发布自己的笔记，请先阅读 [[guides/obsidian-publishing-guide|Obsidian 发布指南]]，再对照 [[reference/markdown-publishing-reference|Markdown 发布规范]] 检查 Front Matter、链接和图片路径。

所有内容与站点代码都在 GitHub 公开维护。发现错误、希望补充案例或提出新主题时，可以通过 [GitHub Discussions](https://github.com/zj75968-cpu/docusaurus/discussions) 参与交流。
